# How accurate is the matching?

Measured against **2354 labeled pairs** of a device and a real FDA recall (410 built from 40 real recalls, plus 1946 unrelated pairs between them), with the right answer decided before the matcher is asked. Generated by `npm run eval`; `npm test` fails when this page is out of date.

**What this is, and is not.** The recalls are real openFDA records (frozen in `eval/recalls.json`). The devices were made from what each recall says (its maker and model, a serial or lot it lists, its UDI-DI, a range it states) and from near misses (another model, another maker, another UDI-DI, a lot code that looks like a range), so the right answer follows from the recall text: it is written down in `scripts/make-eval-set.mjs`. The labels were written by the developer, not by a clinical engineer, and the devices are not a real hospital's. So this is a regression set and a sanity check of how the rules read real recall wording, **not** a measure of how often the app is right in a hospital.

## Known limits (what these numbers do not cover)

- **Very short serials without a UDI-DI.** A serial or lot of fewer than four characters ("209") is not trusted on its own, because such a number turns up in recall texts by chance (`MIN_LOT_LENGTH` in `src/matching.js`). A pair like that is *likely*, not *exact*, even when the recall lists the unit. With the UDI-DI recorded the same unit is *exact* (the `udi-listed-unit` cases).
- **Units a recall rules out.** When a recall states a serial range and the unit is outside it, the matcher still says *likely* for the product: it does not rule units out, because a wrongly read range would hide a real recall. A person decides, and the reason names the range.
- **Wording nobody wrote a rule for.** The set holds the 40 recalls above and the ways they write serials, lots and UDI-DIs. A recall that lists its units in a picture, a link or a PDF cannot be read at all, and is *likely* at best.
- **Not a field measurement.** Labels come from the recall text, written by the developer. A hospital's own device list (typos, old model names, missing serials) will do worse than this set; the number to trust is the direction, not the last decimal.

## Re-running it

```bash
node scripts/make-eval-set.mjs --pull   # fetch the real recalls again (about 40 requests), only when the set should move on
node scripts/make-eval-set.mjs          # rebuild the cases from them
npm run eval                            # measure and rewrite this page
```
